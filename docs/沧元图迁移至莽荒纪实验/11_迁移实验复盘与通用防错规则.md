# 剧情迁移实验复盘与通用防错规则

> 适用范围：后续将《吞噬星空》《雪鹰领主》以及其他作品迁移到《莽荒纪》世界时，必须先阅读本文件。

## 本次错误的最终认定：以后不得再犯

本次前五卷迁移稿把原作116章压缩成25个篇级剧情点，实际完成的是“按卷重编”，不是“逐章迁移”。这是结构性错误，不能再用“已经保留主线”来替代逐章对应。

以后凡是用户要求“完整迁移”“按原作节奏”“每章对应”时，必须遵守以下硬规则：

1. **一章对一章。** 先统计原作章节总数，再建立同等数量的新章节；不得用五个大剧情点代替二十余章，更不得在没有说明的情况下合并章节。
2. **顺序不可擅自重排。** 每章必须保留原章的事件顺序、冲突升级、高潮位置和章末状态；本土化只能替换无法适配的名称、武器、境界、势力和场景。
3. **剧情功能不可被结果替代。** 原作的比赛、营救、悟道、受伤、恢复、追杀、传承和死亡，不能只保留一个“最后成功”的结果，必须保留它们在成长链中的作用。
4. **人物关系先锁定再写。** 青梅竹马、婚约对象、妻子、父母、师尊、同伴和对手必须使用固定映射；新角色不得在不同章节间漂移身份。
5. **新剧情必须有迁移说明。** 如果必须添加、删除或改造原剧情，必须标明“原功能—新事件—改动原因—是否保留结果”，不能把新增内容伪装成原作对应内容。
6. **能力路线不能反过来吞掉剧情。** 先保留原章功能，再把刀换枪、雷霆换土、速度换防御等能力本土化；不能先设计新能力，再强行删改原作事件。
7. **每章必须有可核对条目。** 每章至少写3个剧情点，至少包含事件、冲突/人物关系、结果/后续影响；篇末必须核对境界、地图、角色状态和伏笔。
8. **旧稿必须明确降级。** 只有篇级宏观稿的文件不能继续标为“逐章迁移稿”；它只能作为骨架或历史草稿，不能作为完成品交付。

### 正文写作前的强制门槛

正文不能只依据章节摘要写作。每一章必须先在覆盖审计中完成“原剧情节点—新剧情节点—人物关系—章末状态”四项核对；复杂战斗、突破、追杀和重大转折章必须达到4—7个关键节点。若发现摘要与覆盖审计不一致，先修订细纲，再写正文。正文完成后还要反向检查：是否出现从结果直接跳到结果、是否漏掉受伤/恢复/代价/伏笔、是否改变人物关系或境界顺序。

本规则已经通过 `13_逐章迁移大纲_第一至第五篇_修订版.md` 与 `14_逐章剧情覆盖审计_第一至第五篇.md` 落地：前者负责116章的章节摘要，后者负责每章3—7个关键剧情节点及原作功能覆盖，前五篇按原作23、25、25、21、22章重新建立一一对应，共116章。

## 一、这次迁移已经暴露出的主要问题

### 1. 没有先建立角色一一对应表

最典型的错误是许宁问题：前面已经把苏萍设定为林远的退婚对象，后面又把许宁写成了类似退婚对象的青梅竹马，最终造成女主、退婚对象和青梅竹马三个功能互相串位。

根本原因不是单句写错，而是写作前没有建立“原作角色—新角色—人物功能—关系边界”的固定索引。写到后期时，只记住了“主角身边有一个重要女性角色”，却忘记了原作中不同女性角色承担的是完全不同的功能。

处理办法：新增[角色对照表](09_角色对照表_原作至新小说.md)，并把以下内容写成硬约束：

- 一个原作角色只能有一个主要新角色映射；
- 一个新角色不能同时承担两个互相冲突的原作身份；
- 青梅竹马、婚约对象、师妹、妻子、母亲、敌对女性等关系必须分开记录；
- 同一角色的父母、师承、子女、配偶必须单独列出；
- 尚未落名的角色要标记“待补写”，不能假装已经完成。

### 2. 没有把原作人物关系当作连续性数据维护

之前主要关注“这个角色在剧情中做了什么”，但没有持续维护“这个角色和谁是什么关系”。于是人物虽然单篇看起来合理，跨篇连接时却会发生身份漂移、辈分错位和功能重复。

处理办法：以后每部迁移都必须维护一张关系账本，至少包含：

| 字段 | 作用 |
|---|---|
| 原作角色 | 追踪迁移来源 |
| 新角色 | 固定新小说姓名 |
| 原作功能 | 主角、妻子、师尊、对手、反派等 |
| 新身份 | 本土化后的身份和势力归属 |
| 关键关系 | 父母、配偶、子女、师徒、敌对关系 |
| 首次出现位置 | 防止角色突然出现 |
| 结局状态 | 死亡、失踪、突破、离场或存活 |
| 映射状态 | 已固定、功能位已定、待补写 |

### 3. 没有先区分“剧情迁移”和“世界规模迁移”

这次把《沧元图》29集直接对应成新小说29篇，实际上完成的是“《沧元图》剧情骨架迁移”，不是“《沧元图》剧情完整进入《莽荒纪》规模”。

《沧元图》约193万字，《莽荒纪》约420万字，后者多出16卷。前者的主线可以在三界战争后进入域外并完成收束，后者则在三界终战后还要展开大量外部区域、势力和文明。因此把两者简单按篇数对应，必然会压缩《莽荒纪》的地图。

处理办法：每次迁移开始前必须先选定目标：

1. **骨架迁移**：严格保留原作主要剧情顺序和结局，目标世界只提供本土化背景；
2. **规模迁移**：保留原作剧情功能，但按目标作品的地图、势力和篇幅重新扩展；
3. **融合重构**：保留原作主线与爽点，同时吸收目标作品的地图推进和后期结构。

这三种模式不能混写。若用户说“完整迁移”，必须进一步确认是完整迁移剧情，还是完整迁移到目标世界的规模结构。没有确认时，默认先做骨架迁移，但文件标题必须标明这一点。

### 4. 把“域外”当成一个地名，而不是一套世界结构

当前迁移虽然写到了黑龙星、魔山、青羽馆、蒙刹界、画圣山和乾源山，但很多地点只是连续出现的高阶副本，没有形成大区域、区域秩序、进入资格、资源体系和离开代价。

这会造成一种假象：地名越来越多，但世界并没有真正扩大。

处理办法：每个新区域必须填写六项：

1. 主角为什么进入；
2. 谁统治或影响这个区域；
3. 主角在此获得什么资源、身份或能力；
4. 该区域的主要敌人和竞争者是谁；
5. 主角离开时付出了什么代价；
6. 这段经历如何改变主角、家乡和最终主线。

如果一个地点无法回答这六项，就只能作为场景或副本，不能算作真正的地图扩张。

### 5. 只迁移了事件，没有迁移事件的功能

同一个事件在不同作品中可能承担不同作用。例如：

- 进入宗门，可能是获得传承，也可能是进入更大世界的门票；
- 战胜对手，可能是单纯爽点，也可能是确立势力地位；
- 探索遗迹，可能是拿宝物，也可能是揭示宇宙历史；
- 家乡战争，可能是终局，也可能只是更大宇宙战争的起点。

之前的迁移较多采用“原事件改名后放入新世界”的方式，导致事件顺序还在，但功能层级不够准确。

处理办法：每个原剧情节点都要同时填写：

| 原剧情事件 | 原剧情功能 | 新世界替代事件 | 新事件功能 | 是否保留原结果 |
|---|---|---|---|---|

只有“事件”和“功能”都对应上，才算完成迁移。

### 6. 没有在前期建立地图开放顺序

之前直到发现三界篇过长，才回头分析地图差异。正确顺序应该是先确定：主角什么时候离开家乡、第一次进入什么区域、如何获得更大世界的资格、什么时候接触顶层势力、什么时候进入最终宇宙层级。

处理办法：正式写篇级大纲前，先建立“地图路线表”，包含：

- 地图层级；
- 进入条件；
- 对应境界；
- 主要势力；
- 代表性资源；
- 主要敌人；
- 退出条件；
- 与下一地图的因果关系。

### 7. 没有先做原作体量和结构核对

如果没有先查看两部作品的总字数、章节数、卷数和终局位置，就容易凭感觉认为“两本书字数相近、地图应该差不多”。这次核对后才发现，《莽荒纪》的体量约为《沧元图》的两倍多。

处理办法：每次迁移启动前必须建立一页原作对比表：

| 项目 | 原作A | 原作B/目标世界 |
|---|---:|---:|
| 总字数 |  |  |
| 总章节数 |  |  |
| 卷/篇数量 |  |  |
| 主角境界阶段数 |  |  |
| 家乡篇结束位置 |  |  |
| 第一次外部地图位置 |  |  |
| 终局地图 |  |  |

这张表用于判断是原作差异，还是迁移压缩，而不是等出现问题后再解释。

### 8. 对未确认角色采用了隐性合并

部分原作高层角色在当前迁移中只有职位对应，没有新姓名，例如洛棠尊者、剑九王、天星侯、白瑶月等。如果不标明状态，后续写作很容易把这些功能随意转给秦岳、白石或许宁，进一步造成角色职责重叠。

处理办法：所有角色映射必须使用三种状态：

- **已固定**：姓名、关系、功能和出场位置都已确定；
- **功能位已定**：功能已经确定，但还没有正式姓名；
- **待补写**：原作功能尚未真正进入新小说。

未完成映射不能出现在“已完成角色表”里，也不能在正文中悄悄补写。

### 9. 没有进行跨篇连续性审计

单篇检查通常只能发现局部语句问题，无法发现“前面退婚、后面青梅竹马”“前面已经死亡、后面又出场”“父子关系突然变成师徒”这类跨篇错误。

处理办法：每完成一组篇章，必须做四类审计：

1. 角色关系审计；
2. 境界和年龄审计；
3. 地图进出审计；
4. 伏笔与结局审计。

### 10. 提交阶段曾经出现补充提交

此前项目在提交后又补写状态或推送说明，导致同一任务出现第二次补充提交。问题不是 Git 本身，而是把交付记录和业务修改混在了提交之后。

处理办法已经写入项目规则：

- 所有业务修改一次完成；
- 提交前统一做格式检查、链接检查和状态检查；
- `CHANGELOG` 只记录提交前验证，不因补写推送结果产生第二次提交；
- 一次业务提交后推送工作分支，再快进合并并推送 `main`；
- 远程结果只在最终回复中说明。

## 二、以后每次迁移必须采用的工作流程

### 第一步：原作事实盘点

先读取原作索引、各篇/卷 state 和必要原文，整理：

- 角色全表；
- 女性角色和感情关系；
- 家族、师门、势力关系；
- 地图开放顺序；
- 境界推进；
- 主要比赛、战斗、死亡和终局；
- 重要伏笔及回收位置。

### 第二步：确定迁移模式

明确是骨架迁移、规模迁移还是融合重构，并写入迁移规则总表。后续所有篇章都必须遵守同一个模式，不能前半段做骨架迁移，后半段突然要求达到目标作品的完整体量。

### 第三步：先建三张表

正式写大纲前，必须先完成：

1. 角色对照表；
2. 地图路线表；
3. 原剧情功能迁移表。

三张表都完成后，才开始写篇级剧情。

### 第四步：锁定关系和世界规则

将以下内容列为不可随意修改项：

- 主角唯一姓名和核心性格；
- 女主、青梅竹马、婚约对象的区分；
- 家庭成员和辈分；
- 师尊、同伴、对手、反派的边界；
- 每个阶段的地图范围；
- 境界的先后顺序和突破来源；
- 已死亡、失踪、离场角色的状态。

### 第五步：按“功能”写迁移稿

每个剧情点都要同时说明：发生了什么、谁参与、原作功能是什么、新世界如何本土化、结果是否保留、对后续产生什么影响。

### 第六步：分阶段审计

至少在以下节点停下来审计：

- 前期家乡篇结束；
- 第一次进入外部世界；
- 主角第一次接触目标世界顶层势力；
- 终局战争开始前；
- 全部篇级大纲完成后。

### 第七步：最后才做文字润色和 Git 交付

先修结构、关系、地图和境界，再修语言。所有文件同步完成后统一验证，避免先提交大纲、后补角色表、再补规则文件。

## 三、后续迁移《吞噬星空》《雪鹰领主》的特别注意事项

### 《吞噬星空》迁移前重点核对

- 地球篇、宇宙初期、宇宙国、宇宙海和起源大陆的地图层级；
- 罗峰的武者、精神念师、兽神之道等多路线关系；
- 徐欣、巴巴塔、洪、雷神、真衍王等角色的功能边界；
- 地球守护、族群崛起、宇宙海生存和超脱追求的目标变化；
- 不能把“地球篇的家乡危机”直接当作全书终局。

### 《雪鹰领主》迁移前重点核对

- 夏族世界、红石山、神界、湖心岛遗迹、太虚天宫等地图开放顺序；
- 东伯雪鹰的血脉、虚界幻境、枪道、虚空道和终极境界来源；
- 余靖秋、靖秋帝君、池丘白、剑主、血刃神帝等角色的关系和层级；
- 物质界、神界、混沌虚空和浑源空间之间的结构差异；
- 不能因为前期夏族世界篇完成，就把后期神界、混沌虚空和浑源层级压成结尾几篇。

## 五、正文阶段新增的主角与人物防错规则

前面的迁移规则主要解决“原剧情有没有漏迁移”，本轮正文又暴露出另一类问题：剧情结构虽然成立，主角和人物却可能被事件带偏。以后正文必须额外遵守以下规则。

### 1. 主角目标优先级必须固定

主角的目标按优先级排列：

`热爱并精进自身道路 → 保护家庭和家族 → 参与更大的公共责任 → 追求更高境界和自身道路`

外部案件、妖物袭击和势力阴谋只能作为修炼压力、实战机会、资源来源或保护家人的理由，不能无故把主角改写成侦探、官府办案人或阴谋追踪者。若主角进入某个组织，必须写清楚该组织为什么能帮助他修炼、提供什么资源、有什么代价。

### 2. 天才主角必须自己完成关键领悟

旁人的提示只能负责引爆问题，不能直接给出答案。每一次主角悟道至少要经过：

`旧方法遇到阻力 → 主角自己观察细节 → 尝试并失败 → 自己归纳局部规律 → 获得局部成功 → 明确能力限制`

父亲、师父、教习可以安排训练、提出问题或指出错误，但不能替主角命名能力、总结完整规律、指定突破方向，更不能在主角尚未建立基础时直接拿出高阶传承解决问题。

### 3. 小家族与父辈实力必须匹配

小家族的父亲可以有经验、有责任感、有一门不完整的家传功法，但不能无铺垫地是隐藏神魔或顶层强者。若父亲真有足以改变家族命运的实力，必须同时解释他为什么不能保护家族；解释不成立时，优先降低父亲实力，而不是继续添加秘密。

### 4. 女性角色必须通过功能审查

每次女性角色出场前必须回答：她这次出场是否承担明确的生活、情感、关系或剧情功能？如果删掉这一场，主角目标、冲突和人物关系都不受影响，就删除或合并。

前期女主可以温柔、体贴、少言，提供药物、饭食、照料和家庭温度；她不能为了增加戏份而解释世界、替主角推理、参与不必要的战斗或和主角争夺修炼表现。她的对白要短而有目的，不能用俏皮争辩制造“存在感”。

### 5. 因果和名词必须按发现顺序出现

必须遵守：

`现场现象 → 人物观察 → 初步判断 → 验证动作 → 得出结论 → 产生新行动`

不能先写“阵纹被改过”，后面才让人物发现；不能水里突然出现未引出的目标；不能用一段注释解释阵钉、阵务司或境界。名词第一次出现时，必须由人物正在做的事自然带出用途。

### 6. 文件交付也属于质量控制

当前试写正文必须只有一个统一文件，章节用独立标题分隔；试写稿、拆章稿、过期正文和旧版审计不能与当前正文混放。重写后必须同步更新角色表、设定总表、篇幅统计和成长审计，不能正文已经改了，规则文件还保留旧的失踪、退婚、隐藏父亲和查案动机。
