# 前五篇逐章剧情覆盖审计与扩写基准

> 本文件解决“章节数相同但剧情点不足”的问题。
>
> `13_逐章迁移大纲_第一至第五篇_修订版.md`中的每章3条，是章节摘要，不代表该章只有3个剧情点。本文件把原作每章必须保留的连续事件拆开，作为后续章节细纲和正文的覆盖基准。
>
> 规则：简单章至少3个节点；普通章4—5个节点；战斗、突破、追杀、重大转折章5—7个节点。若新稿为了枪道、土行或莽荒世界本土化而合并节点，必须在“本土化处理”中写明原因，不得静默删除。

## 一、覆盖状态定义

- **保留**：事件功能、顺序和结果均保留，只替换名称或设定。
- **本土化保留**：事件功能和结果保留，但武器、境界、势力或场景改写。
- **待扩写**：篇级摘要已经提到，但正文细纲必须补出过程，不能直接跳到结果。

后续正文写作前，所有“待扩写”节点必须进入对应章节的详细细纲；没有完成覆盖审计的章节不得直接写正文。

## 二、覆盖审计结论

| 项目 | 修订前 | 本次完善后的执行标准 |
|---|---|---|
| 章节数量 | 116章 | 仍为116章，一章不删、一章不并 |
| 剧情点数量 | 每章固定3点 | 按内容丰富度为3—7个关键节点 |
| 战斗章 | 容易只保留胜负结果 | 必须拆出起势、受压、转折、杀招、代价和结果 |
| 修炼章 | 容易从瓶颈直接跳到突破 | 必须保留资源、方法、失败、领悟、再尝试和突破 |
| 人物关系 | 依靠记忆，容易串位 | 每章按角色对照表和关系硬约束核对 |
| 本土化 | 可能重排原剧情 | 只替换无法适配部分，并记录原功能和改动原因 |
| 正文入口 | 可直接从摘要扩写 | 必须先通过本文件的逐章覆盖审计 |

## 三、后续防错流程

以后任何迁移作品都必须依次完成：

1. 原作章节拆分；
2. 每章关键剧情节点拆分；
3. 新小说一一对应；
4. 角色、地图、境界和伏笔核对；
5. 复杂章节扩展到4—7点；
6. 通过覆盖审计后，才允许写章节正文。

只要其中一章出现“原作有事件、新稿无对应节点”，就不能宣称迁移完成。
